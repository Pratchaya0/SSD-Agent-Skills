AI Foundation

เข้าใจว่า LLM คืออะไร และ Prompt ทำงานยังไง

🧠

LLM คืออะไร?

Large Language Model — โมเดลที่ฝึกบนข้อความปริมาณมหาศาล เรียนรู้รูปแบบภาษาจนสามารถสร้างข้อความที่ "สมเหตุสมผล" ต่อไปได้

🎯

Token คืออะไร?

AI ไม่อ่านทีละตัวอักษร แต่อ่านทีละ "token" ซึ่งอาจเป็นคำ, ส่วนของคำ, หรือเครื่องหมาย — ขีดจำกัดการจำของ AI วัดเป็น tokens

Advanced LLM Concepts

คลิกเพื่อขยาย

เมื่อ LLM สร้าง token ถัดไป มันไม่ได้มองแค่ token ก่อนหน้า — แต่ ให้น้ำหนัก (attention weight) กับทุก token ใน context โดยน้ำหนักสูงหมายถึง token นั้น "สำคัญ" ต่อการทำนายมากกว่า

ตัวอย่าง: เมื่อ generate คำถัดไปหลัง "Python ใช้ def สำหรับ function ใช่ไหม" — token ที่มี attention สูงจะถูก highlight

Python ใช้ def สำหรับ function ใช่ไหม → ?

• สีเข้ม/border = attention สูง  • สีจาง = attention ต่ำ

💡 ทำไมถึงสำคัญ? Context ที่ดี = token ที่เกี่ยวข้องอยู่ใกล้ๆ = attention แม่นยำ = output ที่ดีขึ้น นี่คือเหตุผลที่ prompt ที่ชัดเจนและสั้นกระชับได้ผลดีกว่า prompt ที่ยาวและฟุ้งซ่าน
วิธี ทำอะไร ต้นทุน เหมาะกับ
Pre-training เรียนรู้ภาษาจาก internet ทั้งหมด ปรับ weights ทุกตัว $$$$ (หลายล้าน) Anthropic, OpenAI เท่านั้น
Fine-tuning ฝึกต่อด้วย domain data เล็กๆ ปรับ weights บางส่วน $$ (หลักพัน) บริษัทที่มี data เฉพาะทาง
Prompting ให้ instructions ใน context ไม่แก้ weights เลย $ (แทบฟรี) พวกเราทุกคน!
✅ SSD Skills = Prompting — เราไม่ต้อง train model ใหม่ แค่ inject context + instructions ที่ดีผ่าน SKILL.md ก็ทำให้ AI ทำงานตาม standard SSD ได้ทันที

LLM มี knowledge cutoff — รู้แค่สิ่งที่อยู่ใน training data RAG แก้ปัญหานี้ด้วยการ ดึงข้อมูลสด ใส่เข้า context ก่อน generate ทำให้ AI ตอบได้แม่นยำโดยไม่ต้อง retrain

✅ให้ context/ข้อมูลจริงแนบไปด้วย ไม่ต้องพึ่ง memory ของ AI
✅บอกให้ AI cite source: "อ้างอิง line number ที่เกี่ยวข้อง"
✅ให้ permission ปฏิเสธ: "ถ้าไม่รู้ให้บอก ไม่ต้องเดา"
✅Verify output เสมอ โดยเฉพาะ fact ที่ตรวจสอบได้

🧪 Advanced Prompt Techniques

3 เทคนิคที่ช่วยให้ AI ตอบได้แม่นยำและลึกขึ้น

Few-shot prompting คือการให้ ตัวอย่าง input→output 2-3 ชุด ก่อน task จริง AI จะเรียนรู้ pattern จากตัวอย่างและทำตาม format ที่ต้องการ

เหมาะกับ: งาน format-sensitive เช่น commit messages, review reports, naming conventions
SSD ใช้ยังไง: SKILL.md ของ ssd-git-commit ฝังตัวอย่าง commit pattern ไว้ — นี่คือ few-shot prompting ที่อยู่ใน skill
# สอน AI เขียน commit message
Input: เพิ่ม login form ใน React
Output: feat(controller): add login form
---
Input: แก้ bug ราคาคำนวณผิด
Output: fix(service): fix price calculation
---
Input: เพิ่มหน้า dashboard สำหรับ admin
Output: feat(controller): add admin dashboard

Chain-of-Thought (CoT) คือการให้ AI คิดทีละขั้นตอนก่อนตอบ วลีง่ายๆ เช่น "วิเคราะห์ก่อน" หรือ "คิดทีละขั้น" ช่วยให้ AI แก้ปัญหาซับซ้อนได้แม่นยำขึ้น

เหมาะกับ: debug, root cause analysis, architecture decisions, refactoring ซับซ้อน
❌ ไม่ใช้ CoT
"แก้ redirect loop" → AI เดาแก้ อาจผิด
✅ ใช้ CoT
"วิเคราะห์ flow ก่อน แล้วเสนอ fix" → เข้าใจ root cause
# Chain-of-Thought: debug auth issue
ก่อนตอบ วิเคราะห์ทีละขั้น:
1. อธิบาย flow ปัจจุบันของ code
2. ระบุ point ที่อาจเกิด loop
3. เสนอ fix พร้อมเหตุผล
4. ระบุ edge cases
Code: [paste AuthProvider.tsx]

Role Prompting คือการกำหนด บทบาท/persona ให้ AI ก่อนทำงาน AI จะปรับ tone, depth, และ perspective ตาม role ที่กำหนด

เหมาะกับ: code review, architecture review, ต้องการ feedback ที่ strict ตาม standard
SSD ใช้ยังไง: skills ทุกตัว set role ใน context — ssd-backend-review กำหนดให้ AI เป็น "Senior .NET developer ที่รู้ SSD standards"
❌ ไม่มี role
"review code นี้ให้หน่อย"
→ feedback ทั่วไป ไม่ strict ตาม SSD
✅ มี role
"You are Senior SSD Developer
ที่เข้มงวดกับ TypeScript standards
ห้ามผ่าน code ที่มี `any` type
Form ต้องใช้ Formik เท่านั้น"
→ feedback ตรงตาม SSD standard ทุกข้อ
